Filter Bar

Fila de filtros armada 100% con componentes que ya existen en la librería — Input Search, Switch, Select/MultiSelect (en modo display="count") y Button. No tiene una API de estilos propia — se pinta con tailwind.config como el resto de la librería, nada de un objeto classes en runtime.

Uso básico

// fields es una propiedad JS (datos estructurados), no un atributo
<ui-filter-bar id="bar"></ui-filter-bar>

<script>
  document.getElementById('bar').fields = [
    { name: 'q', type: 'search', label: 'Buscar', placeholder: 'Buscar producto...' },
    { name: 'ready', type: 'switch', label: 'Listos para usar' },
    { name: 'uso', type: 'select', label: 'Tipo de uso', options: ['Exterior', 'Interior'] },
    { name: 'superficie', type: 'select-multiple', label: 'Superficie',
      options: ['Maderas', 'Metales', 'Paredes'] },
  ];
</script>

Tipos de campo

typeSe renderiza como
searchui-input-search, con debounce (field.debounce, default 250ms).
switchui-switch.
selectui-select en modo display="count" (badge 0/1, no el valor elegido).
select-multiple / checkboxui-multiselect en modo display="count".

Cada campo: { name, type, label, options?, placeholder?, debounce?, default? }. options acepta strings (['Exterior','Interior']) u objetos { value, label }.

Props (atributos) / API

MiembroTipoDescripción
.fieldspropiedad JS (array)Define los campos. Asignarla reconstruye la barra.
submit"auto" | "button" (atributo)"auto" (default): aplica en cada cambio. "button": agrega un botón "Aplicar", solo aplica al hacer click.
apply-labelstring (atributo)Texto del botón "Aplicar" en modo submit="button".
.valuesgetterValores actuales, por name.
.apply() / .clear()métodosControl imperativo.

Eventos

EventoDetailCuándo se emite
ui-filter-change{ values, changed, applied }En cada edición (antes de aplicar, si submit="button").
ui-filter-apply{ values, changed }Al aplicar — es el evento que normalmente disparás la búsqueda/fetch.
ui-filter-clear{ values }Al limpiar todos los filtros (seguido de un ui-filter-apply).

No hay modo "query params"/URL — la barra no sabe nada de tu backend, igual que AutoComplete no sabe de tu endpoint. Armá la URL vos mismo en el handler de ui-filter-apply si la necesitás.

Responsive

Debajo de md: los campos se esconden detrás de un botón "Filtros" (con badge de cantidad activa) que los abre como una hoja inferior con backdrop — probalo achicando la ventana. Son los mismos elementos de campo todo el tiempo (no se reconstruyen al abrir/cerrar), así que no perdés el foco ni lo que estabas escribiendo.

Accesibilidad

  • Cada campo hereda la accesibilidad de su componente real (label asociado, aria-expanded, foco por teclado) — no hay reimplementación propia.
  • El botón "Limpiar filtros" es un ui-button real, navegable por teclado.
