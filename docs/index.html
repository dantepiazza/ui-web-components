Por qué existe esta librería

Nació de un problema concreto: un mismo panel construido en distintos microservicios, cada uno con su propio framework, reimplementando el mismo botón y el mismo modal una y otra vez.

El problema

Cada framework trae su propia librería de UI, con su propia licencia, su propio vocabulario de props y su propio bundle — y ninguna se lleva bien con las demás en el mismo proyecto.

La solución

Web Components reales sobre Lit, en Light DOM: se comportan como HTML nativo, heredan Tailwind del proyecto que los usa, y funcionan igual sin importar qué framework los renderiza.

Por qué esta y no otra

Lo que otras librerías cobran como plan Pro (autocomplete, date picker, rich text, data grid, kanban...) acá está completo y gratis desde el día uno. Ver la comparativa.

Construida con IA, pensada para que una IA la siga mejorando

Cada componente sigue las mismas convenciones estrictas a propósito: Light DOM, solo tokens nativos de Tailwind, un patrón fijo para exponer eventos y slots. Esa consistencia es lo que le permite a un asistente de IA leer un componente existente y construir el siguiente sin inventar una convención nueva cada vez.

Vamos a publicar una skill de esta librería para que cualquier asistente (Claude, Copilot, lo que uses) sepa de memoria cómo agregar o mejorar un componente respetando las reglas del proyecto — no como una ocurrencia libre, sino siguiendo el mismo librito que seguimos nosotros.

¿Falta un componente, una variante, o encontraste un bug? El proyecto está abierto a contribuciones — humanas o asistidas por IA — siempre que sigan las convenciones documentadas en el README.

Empezar

Dos líneas de HTML te dan el componente andando en cualquier stack. Elegí el tuyo:

<link rel="stylesheet" href="https://unpkg.com/@ui-web-components/components/dist/ui-web-components.css">
<script src="https://unpkg.com/@ui-web-components/components/dist/ui-web-components.js" defer></script>

<ui-button variant="primary">Guardar</ui-button>
// index.html — mismos dos tags que en Vanilla

// app.module.ts
@NgModule({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
})

<ui-button [variant]="'primary'" (click)="save()">Guardar</ui-button>
{{-- layouts/app.blade.php --}}
<link rel="stylesheet" href="{{ asset('vendor/ui-web-components.css') }}">
<script src="{{ asset('vendor/ui-web-components.js') }}" defer></script>

<ui-button wire:click="save">Guardar</ui-button>
// vite.config.js — que Vue no intente resolver ui-* como componente propio
export default {
  compilerOptions: {
    isCustomElement: (tag) => tag.startsWith('ui-'),
  },
}

<ui-button variant="primary" @click="save">Guardar</ui-button>
npm install @ui-web-components/components

import '@ui-web-components/components';

// eventos custom (ui-input, ui-change, etc.) se escuchan con addEventListener,
// React no los reconoce todavía como prop onXxx nativa
<ui-button variant="primary" onClick={save}>Guardar</ui-button>
